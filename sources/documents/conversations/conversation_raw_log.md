## The four mistakes → our stack

**1. No reward system** (Response)  
Print is not the entry. Need **+3 ticks in your direction** after the absorption, and the faded side is **not** being refreshed on tape/CVD. CVD median must agree.  
Absorption **only fades**. Never a hold/continuation trigger.

**2. Wrong auction location** (Location)  
Same print at POC / mid-balance = “THIS IS NOT ABS.” Legal only at a **fixed** extreme: shelf, ledge, LVN, prior-day VA, Jumbo extreme / look-left swing.  
Today’s VAH/VAL still moving = lag. Do not use as the location.

**3. Wrong definition** (Response)  
Sequence, not a blob: aggressive effort → passive wall (sponge) → **no reward** for that effort → **opposite aggression**. Enter on the **retest** of the reward, not on the wall.

**4. Your side has not won** (Response + Context)  
Delta spike where control flips, then the wall. Fastest tell, still worthless at POC. Failed-auction context (left value, coming back) is permission, not a 72–80% button.

## How it sits

```
Context:  Z in {B, failed-auction}, not Discovery. Thesis alive. Fuel not spent the wrong way.
Location: Jumbo extreme ∩ (shelf/ledge/LVN/look-left/PD VA). Not POC. Not live VAH.
Response: sponge + 3-tick reward + delta flip + no refresh of the faded side.
```

Hold trades **do not** use this PDF. Holds use internals + no failed traverse the other way.

## For the model

Do not hard-code 3 ticks or 27%. Those drift. Features:

- `ticks_follow_through` after the print  
- `efficiency` = displacement / aggressor vol  
- `refill_flag` (MBP-1 size comes back)  
- `at_poc` → force skip  
- `va_is_live` vs `va_is_prior`  
- `cvd_side`  
- `seq_ok` (effort → wall → opposite aggression)

Train `P(take | those, Z, location_class)`. The 3-tick rule is the prior, not the law.

## Why I said HMM — and what is better

HMM is the **smallest** thing that matches their language: discrete states `B/A/D/E/W` and `P(Z_{n+1}|Z_n)`. It is a teaching prior, not the production model.

Better, in order of “worth it”:

1. **Semi-Markov / HSMM** — duration in A or D matters (3-tick window is a duration). HMM forgets that.  
2. **Conditional model (CRF / structured SVM)** — transitions depend on features (intensity, refill, location class). That is the actual object: P(Z_{n+1}|Z_n, x).  
3. **Neural Hawkes / marked point process** — tape *is* a point process. Good for intensity + “next flip.”  
4. **Seq model on events** (GRU/Transformer on trade/BBO events) — learns the sponge sequence without you drawing boxes. Needs more data; 3y NQ MBP-1 is tight but usable if you **only** train at tagged locations.  
5. **Two-head classifier** if you refuse sequence: `is_sponge` and `follow_through` with features of the last N events. Often wins on small samples.

Do **not** start with a giant Transformer over the whole session. That is the old “predict next 15m” mistake.

Practical build:

- States stay the PDF alphabet (so you can debug).  
- Emission/transition = **gradient model on x** (pace, efficiency, reload), not a fixed A matrix.  
- Duration head for the reward window.  
- Train **only when Location is live**. Off-location events are not labels.

HMM if you need a readable matrix this month. CRF + duration, or a small event-GRU at the level, is the actual upgrade. Speed of tape is just `x`.

## Assistant

Yes. Two jobs: **propose** levels, **pick** which ones matter *today*. K-means in that script is a weak proposer. CNN-on-a-screenshot is the wrong picker.

## Propose (replace k-means)

**DBSCAN / HDBSCAN** on `(price, time, signed size)`  
- Does not force `k=4`.  
- Density = real shelf; noise prints stay noise.  
- HDBSCAN gives a stability score per cluster.  

Also valid: 1-D kernel density on volume/delta at price (that *is* a profile). Peaks = HVN, troughs = LVN. Same objects, no cartoon clusters.

**Not** a 2-D CNN on the chart image. That learns candles and colors. If you want a conv net, run it on the **profile vector** (volume and delta per tick), 1-D CNN / TCN — that is “CNN for levels” that is not a meme.

## Pick (the actual model)

Hundreds of candidates in: Jumbo, look-left, VP peaks, HDBSCAN shelves, VS, prior VA.

**Daily ranker**, not a generator of magic prices.

Input per candidate, **that morning**:  
distance to ON H/L, open vs VA, signed size, cluster stability, age, touches so far, IV/GEX nearby, cycle.

Output: `P(this price is a reception / session extreme today)`.

Train listwise (LambdaMART / CatBoost rank) on history: label = did it become HOD/LOD, second test, or 1R swing. One row per (day, candidate).

The “discretion” is **which object wins today**, not inventing a line.

## “In between” / low confidence

Do **not** let the net draw a naked price.

- If two scored objects sit close → emit the **volume-weighted midpoint** (or the VP POC of that pocket). That is a real in-between.  
- If nothing is high-confidence → **pass** or trade smaller at the top-1 with a wide stop. Guessing a third price with no object is the old generator.

Low confidence is a **size** output, not permission to hallucinate.

## Day-specific without refitting every dawn

The ranker is global. Features are **today’s** state. That is already “for that specific day.” Adaptive half-life on the ranker only; the object list can stay.

Pipeline: HDBSCAN + profile peaks → 20–40 objects → ranker keeps 2–3 per side → Response at those only. CNN image models stay out.
