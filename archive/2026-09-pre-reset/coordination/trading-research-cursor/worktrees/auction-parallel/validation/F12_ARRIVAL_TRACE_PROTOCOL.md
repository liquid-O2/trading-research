## Scope and boundaries

Implement a narrow offline F12 adapter and independent literal reference around existing data, scheduler, publication, quality and simulated order kernels. Do not rewrite those kernels to impersonate measured capture. Use a new module proposed at src/trading_research/runtime/arrival.py, independent reference at references/arrival_literal.py, and tests/test_arrival.py. Any edit to shared runtime ports/verify is a separately reviewed minimal registration/caller binding. No SDK, network connection, provider authentication, live market read, order submission, broker reconciliation, economic run, model fit or source-document execution. An order-ack record is supplied synthetic boundary evidence, never a sent order. Every resulting artifact must say simulated_boundary=true and actual_live_evidence=false for these toy fixtures.

The registered service name is proposed as F12.ARRIVAL_TRACE.v1 with RAW_APPEND, REPLAY, CHECKPOINT, PARITY and TELEMETRY operations. Exact runtime graph binding is subject to root approval before code. RAW_APPEND produces immutable raw transport receipt evidence. REPLAY consumes a finite committed trace and explicit callback registry. CHECKPOINT binds trace prefix and callback states. PARITY compares versioned observable outputs. TELEMETRY reports qualified lag samples/counts. F12 does not grant downstream field eligibility or substitute for existing F01/F05/F06/F07 contracts.

## One record schema

ArrivalRecord v1 is an immutable JSON-compatible record with required schema_version=1, trace_id, arrival_ordinal (nonnegative strict increasing within trace), delivery_id (unique in trace), kind, boot_id, receipt_utc_ns, receipt_monotonic_ns, provenance (actual_capture|modeled_scenario|synthetic_fixture), and payload. Optional clocks are source_event_utc_ns and provider_published_utc_ns; absence is null, not zero. UTC clocks are signed int64; monotonic clocks are nonnegative int64. Reject booleans as integers, nonfinite values and unknown schema/enum values. Strings identify a specific nonempty namespace. Canonical serialization is UTF-8 JSON with sorted keys, compact separators, no NaN, and exact integer clocks. Forbid bytes-as-float and unbounded arbitrary objects.

Kinds are source, timer, completion, decision, order_ack, connection, subscription, gap, cursor, clock_adjust and boot. These all share arrival ordering and receipt envelope. Source payload includes source_id, instrument/definition identity, stream_generation, optional provider_sequence and provider_cursor, economic_id (nullable unless the reducer needs dedup), semantic_kind (snapshot|trade|other), raw_hex, raw_sha256 and decoder_id. Raw bytes are exact decoded raw_hex; never hash display text instead. Malformed source bytes are retained even if decode later fails. Different deliveries of one economic event have distinct delivery_id values. Repeated append of the same delivery_id and exact record is an idempotent write retry; any changed record under that ID is a conflict. A received retransmission must have a new delivery_id even when raw bytes/economic_id match. Economic dedup is downstream by declared source namespace, economic_id and definition; equal content without an ID is not sufficient to dedup. A same economic_id conflicting semantic payload is an explicit integrity incident, never silently last-wins.

Timer payload has timer_id, registered callback_id and due_boot_id/due_monotonic_ns; optional recorded due UTC is diagnostic. Completion has job_id, callback_id, immutable input_version_ids, start_boot_id/start_monotonic_ns, and result. Decision has decision_id, callback_id, served_version_ids and action; ack has order_id, ack_id, state_version, economic_known_at and simulated_boundary=true. All of these are provided trace facts; replay must not create a real thread, sleep, use current wall time, add a modeled delay to actual completion, or submit an order. Version payload canonical hashes include definition/kernel identity and semantic state. Retain transport/provenance hashes separately; they cannot be erased to force parity.

Connection payload records source_id, generation, status (connected|disconnected|denied) and reason. Reconnect starts an explicitly new generation before a provider sequence/cursor reset is admitted. Subscription payload has source_id, subscription_id, generation, operation (subscribe|unsubscribe|denied) and instrument scope; it changes source capability prospectively and retains denials. Gap payload has source/generation, gap_id, status (open|closed), reason and optional expected/received ordinals with evidence ID. Cursor records provider cursor and generation as opaque values, not market timestamps. Clock_adjust records old/new UTC and paired monotonic evidence; boot records declare epoch transitions. Keepalive is connection liveness only. Absence of a trade is not gap evidence.

## Durable raw append before decode

Use a local single-writer journal, a declared supported filesystem and a bounded length-prefixed canonical frame with payload SHA256 and monotonically increasing ordinal. Append commits only after write-all, flush and fsync(file); when creating journal/checkpoint, also fsync the parent directory. Decoder callbacks may run only after successful durable commit. Persist the entire original receipt record before normalization or routing, including raw bytes and source/reset/denial markers. The golden fault harness must observe operation order and inject write/fsync/decode failures; no hardware power-loss durability claim follows from a toy fault test. A failed fsync returns an uncertain-commit error and dispatches nothing; reopen/recover determines whether the complete record exists, then exact delivery-ID retry may finish without duplication. Do not report a decoder error as an uncommitted raw record.

On recovery, validate schema, lengths, hashes, ordinals and duplicate IDs from the start. A torn final frame is classified explicitly with retained tail bytes and offset, not silently discarded. Recovery may create a clean new journal generation from the verified committed prefix only under an explicit recovery method that records quarantine evidence; do not mutate the original archive. Interior checksum/length corruption fails closed at its first offset and cannot skip ahead. File locking rejects a second writer or declares unsupported locking before writing. Bounds proposed for this finite implementation: 4096 records, 1 MiB raw record, 64 MiB journal, 64 callbacks, 16 MiB checkpoint; exceeding any bound is explicit before dispatch, never an eviction. Failed append cannot partially advance in-memory dedup/ordinal state. A valid trailing frame following an uncertain fsync is replayed exactly once on recovery; its actual persistence is reported with scope, not guessed.

## Replay, clocks and callbacks

Replay order is committed arrival_ordinal, never sorted source time, provider sequence or adjusted UTC. arrival_ordinal is the observation cut for fidelity comparisons. A UTC query is permitted only under a declared mapping/uncertainty policy; it cannot silently reorder records across a clock adjustment. Receipt monotonic values must be nondecreasing within each boot. Monotonic elapsed is end-start only inside the same boot, otherwise unavailable with reason cross_boot. A backward UTC step is preserved and flagged; UTC source/provider-to-receipt differences remain signed diagnostics with synchronization uncertainty. Negative UTC lag is not converted to zero. Actual measured distributions admit actual_capture with adequate comparable clock evidence only; fixture and modeled samples have separate labels.

Register callback IDs, version hashes, accepted kinds, state schema, immutable initial state and explicit function objects at construction. Reject missing callbacks before advancing a record; do not dynamically import modules or execute code strings from the trace. Callbacks are pure deterministic offline transitions (state, record) -> (new JSON state, observable output list); reject unsupported mutable/nonserializable results. They receive no clock/network/broker service. This is an explicit trust contract for supplied Python functions, not a security sandbox. Callbacks receive detached canonical copies of state/record; mutation of a passed object cannot mutate the committed state. Atomic publication advances driver state/output/cursor only after all record callbacks succeed. Callback error leaves prior driver state unchanged and is replayable; externally side-effecting callbacks are prohibited and cannot claim exactly-once. Kernel wrappers preserve their own eligibility/dedup/scheduling/order semantics. No raw monotonic timestamp is fed to an existing UTC-only kernel pretending to be UTC: wrappers use declared trace-logical time for synthetic boundary ordering and preserve economic/UTC clocks separately; any incompatible kernel clock contract is an explicit gate or adapter rejection. The synthetic wrapper clock maps ordinal n to declared logical time n; it is labeled synthetic logical time and never included in UTC/receipt latency metrics. Actual economic observation clocks remain unmodified in source payloads.

All timers/completions/decisions/acks used for parity are explicit supplied records. An offline projection may emit candidate outputs to compare with recorded decision/completion evidence but must label projection, use the same input versions and recorded availability, and never overwrite evidence. A timer can fire without a trade. A completion already containing actual finish does not receive additional latency. A restarted replay uses captured completion facts, not OptionalWorkers live-thread restart. A stale order ack is retained but cannot regress state; rejection is observable. Existing independent protection remains outside a feed-dependent entry gate.

## Checkpoint, restart and diagnostics

Checkpoint contains schema/definition/policy/kernel/callback registry versions, trace_id, immutable consumed prefix digest, next ordinal, last delivery IDs or complete dedup state, per-source generation/subscription/cursor/gap state, clock boot mapping, callback states, output history or its retained digest plus required served versions, and simulated-boundary/provenance labels. Canonical checkpoint bytes and digest must be identical for the same state; no created-at/current-clock metadata enters semantic bytes. Write a separate temp file, fsync it, atomic replace and parent-directory fsync. Restore validates every bound, prefix digest, registry/state schema and source identities before exposing state. A changed prefix/callback version, corrupted checkpoint or missing required journal prefix is rejected. Interrupted checkpoint cannot replace the last committed checkpoint. Restart mid-event resumes before or after the atomic record boundary, never half a callback. Replay the remaining suffix and compare full outputs and final checkpoint with uninterrupted replay.

Parity compares every record-boundary observable: decision action, semantic state/version, served input versions, publication/availability ordinal, record identity and typed omissions/incidents. Report semantic mismatch, timing mismatch, transport-only difference and numeric difference separately. Exact integer fixtures have zero tolerance. Independently justified future numeric tolerances require another registration; no tolerance introduced after failure. Both provenance and semantic hashes are present; equal semantic hash with changed actual receipt is explicitly timing/transport difference, not unconditional parity. Reference is a simple finite list fold; optimized adapter uses the same declared callbacks/kernels but separate driver/journal orchestration. Reference must not call the candidate driver or use its computed outputs as goldens.

First-divergence diagnostic scans fixed record cuts in ordinal order, reports the earliest unequal cut and both comparable observables, then returns the shortest original prefix that contains that first mismatch. This means minimal leading prefix, not arbitrary event deletion or delta debugging; it requires no monotonic-mismatch assumption. Named deterministic fault plan v1 maps supplied integer seed to explicit ordinal transformations using a documented integer-only schedule, retains original/transformed trace hashes, fault names/parameters and affected IDs. Draft bounded mapping: delay_one chooses index seed % eligible_count in ascending eligible source ordinal, shifts only that receipt logical ordering according to explicit target slot (after all original records at the target logical time, with original ordinal as stable tie-breaker), and resequences a derived trace with an origin mapping. Seed7 on eligible_count3 selects zero-based index1. Reject an invalid target or generation/monotonic inconsistency; never silently repair timestamps. Other fault fixtures can use an explicit named literal schedule and seed as provenance; no unsupported pseudorandom portability claim.

## Telemetry and resource evidence

Report source/session/provenance and clock-pair method for each lag. Nearest-rank quantile is sorted sample[ceil(p*n)-1], p in {0.50,0.95,0.99}; empty sample -> null and reason. Separate receipt-to-completion same-boot monotonic duration from source/provider-to-receipt UTC lag and modeled delays. For n=3 values[1,2,9], p50=2,p95=9,p99=9. These are synthetic arithmetic expectations, not measured live latency. Drops require an independently evidenced expected-delivery population in a declared source/generation/window. expected4, distinct received3 -> missing1, rate1/4. Without expected-count evidence, denominator/rate are null. Duplicates count separately and cannot increase unique received above expected. Gap markers do not automatically reveal the number of missing market events. Reset/subscription changes split populations. Poll versus stream comparisons use common information cuts; equal endpoint state cannot establish equal intrainterval path.

Actual test worker wall/CPU/RSS and file sizes may be measured by root only after registration and whole-batch static review/fix. Proposed envelope for root review: combined family worker at most3 attempts, 600 total CPU seconds, per-attempt180 soft/190 hard CPU seconds, 240 wall seconds, 4 GiB address space; share the physical execution identity and charge full cost to each included family. No standalone test now; envelope not registered by this draft. Candidate/reference scans, journal bytes and callbacks are instrumented separately. No speed, latency or hardware capacity claim from these bounded fixtures.
