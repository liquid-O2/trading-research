# Lossless evaluation storage and bounded cost correction

This representation is prepared for registered check12. It has no successful execution or speed claim until that check's results are retained. The original scientific protocol, analysis/model plans, source variants, chronological cohorts, targets, metrics and1,000 uncertainty replicates remain unchanged.

Check11 completed the actual20-date evaluation resource unit. Its433 groups, six classes and20 metrics used5.020792464 CPU seconds for scoring and14.726496479 for serialization, with123,578,622 uncompressed bytes. The later253-date unit was interrupted at the90-second CPU ceiling. The original failure and spending remain in the same family.

The array scorer exposed the same calibration dictionary as both `calibration` and `calibration_by_class`. Every scalar result also repeated its support and bootstrap-policy dictionaries. The new `jumbo-grouped-date-evaluation-tables-v1` representation stores statistic rows and policy rows once, with exact references from all original groups, metrics and calibration cells. It retains both names through an explicit alias when expanded. No approximate numeric matching, rounding, uncertainty reduction or group omission occurs. Signed zero and scalar types are retained. Missing nonfinite values follow the pre-existing JSON-null policy.

`pack_grouped_evaluation` produces the compact grouped value. `expand_grouped_evaluation(value)` reconstructs the previous published shape. Its optional `group_ids` argument permits one group to be inspected without expanding every other group. Every target still carries its full intended-date universes and exact prediction-row artifact; the existing omission of per-metric date vectors is unchanged. The compressed artifact remains JSON in gzip, with the nested representation declaring its own schema and columns. Overall scores remain in their original readable structure.

The actual20-date check compares every published field against the exact scorer retained from registered check11, including all empty groups, calibration endpoints, support counts and bootstrap diagnostics. It requires64-bit equality of finite floating values and the same missing-value policy. Separate literal cases cover multiple events/date, point and interval labels, lost fields, broken references, independent group loading and signed zero.

Probability-bin membership is computed once per input class. Stable grouping then identifies observed date/bin cells; multiple-event cells use the same ordered `mean` calculation, while a singleton retains its exact scalar. Empty cells remain in the output and receive the unchanged bootstrap/missing-support rules. This removes repeated full-population scans and empty-cell searches without changing calculations.

Resource measurements use the actual production tree basis: linear/full features and the declared comparator features. Classification and quantile trees are measured separately at10 and20 iterations. Linear solvers use both iteration caps on both10/20-date row cohorts. Projections separate setup from iteration work and retain the full declared100 linear/60 tree iterations, actual full feature widths, all declared heads and the existing uncertainty multipliers.

The code review also found that the former all-target tree guard could skip a declared tree target when an unlisted target shared its fused linear family. The corrected fitter preserves that family and all its comparator features, fits each declared tree target, and records target-specific applicability/failure states. Unlisted siblings do not become tree comparisons; one head's failure cannot disqualify another successfully fitted head. This completes the already declared comparisons without adding a hypothesis search.

The next full stage remains gated on a successful applicable check and the completed CPU, memory, output and cumulative-resource projection. The sole purpose of the resource measurements is feasibility; they establish no predictive quality or Location quality.
