## Why the original runbook allowed this

The prior pack already required causal clocks, verified dependencies, native coverage and negative tests. Its acceptance loop still allowed the implementer to write the verifier, set its own A01–A06 booleans, test a few hand-built cases, and use that same verifier's success to declare completion. Required artifacts were named without a fully specified enforcement/evidence contract; review concentrated on the decision trail; native/date scope could be replaced with calendar/synthetic checks. The correction therefore changes both executable checks and the handoff structure.

[ASSURANCE.md](/workspace/planning/research-program/ASSURANCE.md) now specifies exact artifact/identity/command/dependency rules, per-check evidence, native coverage and a separate review bound to the actual candidate. [ASSURANCE_CASES.json](/workspace/planning/research-program/ASSURANCE_CASES.json) assigns concrete positive/negative cases across every task. Generated cards/prompts/runbooks inherit those requirements and the plan checker rejects missing coverage. The fixed independent foundation checker is outside the implementation writer's ownership. Earlier evidence remains immutable under an explicit [amendment](/workspace/planning/research-program/AMENDMENTS.json).
