# Binding computation order and port semantics

This schedule resolves direction where a component card’s dependency field also names downstream consumers. It is part of [CC-01/03/05/06](COMMON_CONTRACTS.md), not an optional diagram. A `Measurement` port, a learned `Forecast` port, a frozen model artifact and a pre-decision account snapshot are different dependencies even when owned by the same component. The eventual registry must declare each input port, time cut, model/fold version and output port, then reject cycles before training or replay.

The [runtime scheduler](RUNTIME_SCHEDULER.md) makes this a multi-rate dependency graph: each producer runs at its registered trigger/cadence and publishes only completed eligible versions. These stages are not a lockstep requirement on every tick. Critical order/risk events have an independent lane.

The binding [full-system upgrade constructions](../UPGRADE_CONSTRUCTIONS.md) add explicit observed-state versus forecast ports for profile/auction/node evolution and early-quality versus late decision sensitivity. Incorporate their final port/target table before implementing those variants. Their 153 parent paths and 191 child bindings extend this graph; they do not permit current-cut feedback, hidden fitted transforms or new incompatible target conversions.

## Within an observation batch

Freeze the admitted observation set and a reconciled pre-decision account snapshot. Late arrivals create a new batch; they never alter an already dispatched decision. Each row below may contain independent work, but within-row dependencies still follow the stated suborder. Every computed output becomes usable only at its recorded completion/availability time. If a long calculation completes after its desired cut, downstream latency and price are updated or the result expires.

S0 has an explicit nonrecursive suborder: F01 raw decoding plus as-of F02 metadata/calendar bootstrap → `F06.RAW` schema/sentinel/integrity precheck → F05 normalized events and correction identity → `F06.SEMANTIC` event/coverage quality → F07 operation-specific as-of eligibility. A raw precheck does not depend on normalization it is meant to precede; normalized semantic checks do. Final operation eligibility can use the normalized fields without feeding back into the same event decoder. Keep raw, semantic and eligibility ports distinct in the compiler rather than turning mutual component-level references into F05↔F06 recursion.

G03 has separate offline `fit` and runtime `apply` functions. Applying a frozen calibrator at an expert, mixture or value stage adds no reverse dependency from its downstream consumer. Calibration training must use the chronological predictions of the corresponding complete upstream chain, including its gates and missingness policy.

Coherence reconciliation under CC-04 is an explicit versioned port in that chain, including its fit dependencies if learned. Register the final ordering of calibration, coherence projection and applicability/selection, then evaluate the emitted distributions after all transformations. Do not claim pre-projection calibration for a subsequently changed forecast. A fitted calibrator, imputer, representation or gate belongs to the OOF training closure just as a main predictor does.

G09.MASK uses raw input validity and previously fitted support/missing-pattern state at the relevant producer’s stage. It may use O21.quality measurements once available, but not current downstream forecast reliability. G09.SELECT sees completed forecasts/value uncertainty and can reject an action; it cannot revise same-batch G01/G02 weights and rerun them until a desired value appears. Producer-local quality masks remain possible even when options are entirely absent.

## Response and management variants

The initial Context/Location policy has no Response prerequisite. In the deferred program, raw R measurements and completed sequence states can be computed from the same prefix without reading current action values. L19 aggression objects originate from M11 observations; a later R confirmation creates a new object/state version rather than backdating its birth. Sequence components requiring a Location consume the frozen base object version, not their own subsequently refined object.

For value comparisons, preserve the baseline G forecasts and immutable opportunity set. An augmented R19 variant consumes those forecasts plus R observations and runs one separately identified augmented G06/G07/G08 pass. R21’s mixture uses frozen C/G context and the available R specialist predictions; it cannot feed the baseline mixture that supplied its context. Compare baseline versus augmented complete policies, including delay, price change and non-fill. A policy may deliberately wait for a future event, but it can use that event only in a later observation batch.

P03 residual-value/trailing decisions use current observed position state and a declared candidate set of full-position exit/hold/stop-update actions. A previous stop/target is data for the new decision, not a request for a fixed-point optimization. Enumerated plans must preserve risk invariants; the model cannot choose its own hindsight stop or relax a reservation after observing a loss.

## Training graph and version rules

An edge between learned predictors is also an OOF edge: downstream training consumes chronological predictions made without the downstream example’s future label or evaluation interval. For jointly trained alternatives, the entire joint model is contained inside the fold; frozen intermediate representations alone do not cure upstream training leakage. Primitive and refined ports have distinct target/feature/model IDs and are independently ablated.

Same-batch refinements require distinct output IDs and a finite ordered graph. Lagged feedback explicitly declares the previous batch/time, maximum age, eligible maturity and state reset. Merely assigning a new version to a recursive forecast does not resolve circularity. Any substitution of a refined port for a primitive one requires re-compiling the graph and regenerating OOF predictions; it is a new registered trial.

## Fixtures to build

`T-DAG` rejects unknown ports, current-edge cycles, consumer-to-producer feedback, mixed decision cuts, invalid lag claims and non-topological OOF fitting. Required negative fixtures include C03↔C06; C06→G02.PATH→C06; C19→O22→X06→C19; O02→X02.bootstrap→O02; G01→G09.SELECT→G01; and current selected P01 action as an input to its own G06 value. Positive fixtures include frozen calibration at each stage, X02 raw parity before IV, absent-IV raw options flow, independently scored X09 child measurements, and one-pass augmented Response evaluation. The source-prefix and restart invariants must hold through the compiled graph, not only inside isolated components.

This is a reviewed specification. No runtime graph, production modules, strategy tests or trained artifacts have been implemented by writing this document.

Additional third-review negative graph fixtures: reject O10→C15.SCENARIO→O10, O12→C15.SCENARIO→O12 and X06→C16.JOINT_STRESS→X06 at the same cut. A jointly trained multi-task alternative is one fold-contained producer with explicit input/output ports; it does not waive the graph or OOF rules.
