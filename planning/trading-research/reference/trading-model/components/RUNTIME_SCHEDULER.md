# Runtime scheduling, state and forecast publication

This is a binding elaboration of F04/F09/F11/F12, the [computation DAG](COMPUTATION_SCHEDULE.md), and [common contracts](COMMON_CONTRACTS.md). It specifies future implementation; no measured latency or functioning runtime is claimed. Component IDs identify responsibilities, not a requirement for hundreds of processes or a neural model for every formula.

Apply [UPK-01 incremental computation](../UPGRADE_CONSTRUCTIONS.md#upk-01) and the construction document's new-port table when optimizing or adding forecasts. Compare reference and incremental schedules at identical information/decision clocks first; altered cadence, request expiry or delayed useful outputs can change the policy and require separate decision evidence. Late sensitivity diagnostics can guide the next cycle, never recursively rebuild their own current inputs.

## Independent clocks and publication

Maintain an event ledger, a strategy-availability clock, a computation-completion clock and an independent account/boundary timer. The DAG orders dependencies whenever a producer runs; it does **not** require all stages to run for every tick. A decision reads completed, immutable producer versions eligible at its information cut. Each carries observation cut, completion time, source age, coverage, target horizon and expiry. New data never changes an earlier decision.

Provisional engineering defaults for benchmarking are a one-minute board update and a two-cycle board lifetime, with comparisons at one, two and five cycles. These are sensitivity scenarios, not verified market freshness limits. Validate permitted TTL by target horizon, source observation/liveness and signal survival. Critical executable quotes/positions do not inherit an optional-source TTL or a permissive two-minute carry rule. Record snapshot age, last source quote/event observation, last actual value change, last receipt and source liveness separately. A healthy unchanged standing quote is valid under its source contract; copied snapshots alone cannot certify continued observation. Daily/weekly reports have their own publication cadence and age rules.

## Atomic decisions and degraded modes

An observation cut creates a version vector of inputs. Work begun on that cut cannot silently splice in a later surface, changed object band or account balance. If it completes late, recompute feasibility against current executable price/account state, or expire it. The predicted horizon starts at the forecast cut, so a stale forecast has less remaining time; do not restart its horizon merely because publication was late. Any target transformation needs an explicit conditional-update model.

Serialize intents through the order state machine. Immediately before dispatch, recheck the critical-state version and reserve risk atomically. If either changed, invalidate the intent and produce a new decision; a valid prediction is not a reservation. A pending order occupies the relevant action state until cancellation/fill is resolved. Two workers cannot independently send the same one-mini entry.

Under overload, coalesce superseded **optional computation requests**, retaining their cut IDs and drop reasons. Never drop raw events, order events, risk timers or already dispatched records to hide overload. Bound active objects with an explicit overflow policy: retain an archive and disclose any scoring cap. Compare cap-induced lost opportunities with a complete offline reference; top-k truncation is an experimental policy, not invisible data cleaning. Cache by data/definition/model/fold/cut hash. Checkpoint all persistent state needed for equivalent replay, including unknown-side accumulators, object visits, reports assimilated, unfinished bars and pending intents.

## Runtime tests and measurable acceptance

`F04.SCHEDULER` tests a slow surface fit during a valid NQ contact; an optional ES outage; a boundary timer during stalled model inference; late publication of a forecast whose horizon partly elapsed; stale same-valued snapshots; restart during an unfinished bar; and duplicate dispatch workers. The first two may degrade optional evidence, but must not create future joins. The boundary test must execute its independent path. The late forecast must expire or retain the original end. The duplicate-worker case permits at most one reserved live position.

Measure p50/p95/p99 completion and dispatch delay, queue backlog, stale/expired forecasts, overflow, decision population changes, peak memory and replay disagreement. Evaluate their economic effects in P05/P06/V06, including trades lost through computation delay. Match training samples to the actual decision scheduler; use background/candidate weights only for a stated population with known inclusion probabilities. A model trained at all touches cannot be evaluated as if it predicted every arbitrary clock cut.

State-machine correctness has zero unexplained semantic failures. Timing budgets become binding only after representative replay/telemetry measurement; a faster benchmark must preserve prefix and restart equivalence. Fewer processes, shared feature kernels, separate heads and compact models are all valid implementations if independent experiment IDs, predictions and diagnostic ownership remain intact.
