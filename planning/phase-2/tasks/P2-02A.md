# P2-02A — Source context baselines: the authors' own reads, measured

Subphase: `03-joint-volatility` (first task). Blocked by: P2-00, P2-01, P2-02. Added 2026-09-16 at the user's direction: the discretionary authors' context rules are the baseline that every fitted context expert is compared against, the same way B0.2 is the baseline for entry rules in Phase 1.5.

## Delivers

Deterministic, causal implementations of each source author's own context read, taken from the wiki predicates, measured on the full population with plausibility gates, and issued at the same snapshots and against the same targets the fitted experts use. Every later expert (joint volatility, range path, auction session, flow memory, cross market, options scenarios, intraday OI, the method experts) is evaluated paired against the applicable source baseline as well as against constant, session-frequency and price-only baselines; an expert is an upgrade only when it beats the source read under the promotion gates, and otherwise the source read is retained. When done, a reader can see, per author and per read, how often the author's rule fires, how well it does on the data, and whether our models add anything to it.

The reads, by method, each with its wiki objects:

- JJ-TBR (Jumbo): the day read that precedes an entry: range width expectation classes ([range-width-context](/workspace/wiki/range-width-context.md)); the causal call of the coming range path, single break versus double break versus rotation ([range-path-class](/workspace/wiki/range-path-class.md)); accumulation, manipulation and distribution phase labels ([amd-phase-labels](/workspace/wiki/amd-phase-labels.md)); opening location and participation ([open-location-switch](/workspace/wiki/open-location-switch.md)); session cleanliness ([clean-session-label](/workspace/wiki/clean-session-label.md)); relative volume at the open ([relative-volume](/workspace/wiki/relative-volume.md)); the EVRange expected move and SessionStat+ envelopes ([ev-range-expected-move](/workspace/wiki/ev-range-expected-move.md), [sessionstat-9-12-envelope](/workspace/wiki/sessionstat-9-12-envelope.md)); reversal and action windows ([reversal-time-window](/workspace/wiki/reversal-time-window.md)); failure signatures and three attempts ([jumbo-failure-attempts](/workspace/wiki/jumbo-failure-attempts.md)).
- SIRES: the regime and thesis read: source gamma regime, flip, walls and max pain, Vol Trigger and VOL-GEX, hedging pressure, KG1, VIX and VVIX context, the volatility-implied daily move and term-structure change ([gex-regime](/workspace/wiki/gex-regime.md), [gex-flip](/workspace/wiki/gex-flip.md), [gex-walls-and-max-pain](/workspace/wiki/gex-walls-and-max-pain.md), [volatility-trigger](/workspace/wiki/volatility-trigger.md), [vol-gex](/workspace/wiki/vol-gex.md), [hedging-pressure](/workspace/wiki/hedging-pressure.md), [kg1-level](/workspace/wiki/kg1-level.md), [vix-context](/workspace/wiki/vix-context.md), [expected-daily-move](/workspace/wiki/expected-daily-move.md), [volatility-curve](/workspace/wiki/volatility-curve.md), [vvix-context](/workspace/wiki/vvix-context.md)); the operational day taxonomy and asymmetric risk state ([asymmetric-risk-state](/workspace/wiki/asymmetric-risk-state.md), [asia-range-risk-context](/workspace/wiki/asia-range-risk-context.md)).
- SAINT-AMT: the higher-timeframe structure read: balance, trending or new balance with POC and value migration ([auction-balance](/workspace/wiki/auction-balance.md), [value-area](/workspace/wiki/value-area.md), [profile-poc](/workspace/wiki/profile-poc.md)).
- MEMBER-TWO-REASONS: prior reaction area memory and the independent minor high-volume node ([hvn](/workspace/wiki/hvn.md), [lvn](/workspace/wiki/lvn.md)).
- KEANI-OPEN-ABOVE-VALUE: the open read, whole A period above prior value and developing value higher ([developing-profile](/workspace/wiki/developing-profile.md), [value-area](/workspace/wiki/value-area.md)).
- Green Bird (GB-FAIL, GB-VWAP, GB-SCALP): the session read: finished session references, London and Asia highs, the midnight true-day open, new-week gap, premium or discount, setup quality grade ([session-fail-boxes](/workspace/wiki/session-fail-boxes.md), [true-day-open](/workspace/wiki/true-day-open.md), [new-week-opening-gap](/workspace/wiki/new-week-opening-gap.md), [premium-discount-50](/workspace/wiki/premium-discount-50.md), [quality-grade](/workspace/wiki/quality-grade.md)).
- Research processes where the source supplies labels: jetbundle participation and auction states, the Stoic macro process, Refill memory ([method-jetbundle-auction-states](/workspace/wiki/method-jetbundle-auction-states.md), [method-stoic-data-engine](/workspace/wiki/method-stoic-data-engine.md), [method-refill-effect](/workspace/wiki/method-refill-effect.md)); scheduled news and changing information ([news-event-context](/workspace/wiki/news-event-context.md)).

Each read is a causal function of owned data at the snapshot clock returning the author's call (a class, a level, an expected move or a suitability flag) and its unknown reason when an input is unavailable. A read that needs a proprietary feed the sources do not publish (for example an author's gamma vendor) is `unsupported_owned_input` with the operand named; it is never approximated silently.

## Steps

1. Register every read above in `SOURCE_CONTEXT_RULES.json` with its wiki page, its operands and their ledger classification (source-exact, printed-but-different, inferred, not identifiable), its output kind and the expert targets it is a baseline for. Implement the first read end to end as the vertical slice with the sensitive positive case and a negative control from the wiki's worked example.
2. Implement the remaining reads; run the plausibility gate over the full history: each read's call frequencies per session against the source's stated frequencies where printed, otherwise reported with a diagnosis; nothing is tuned to results.
3. Issue every read on the P2-01 snapshot rows; measure base rates and the contract's losses per fold with the block bootstrap and support gates; run the declared slice, inspect the output, then the full run.
4. Trace one call per method through its serialized row to the wiki predicate and the native receipt; write the paired-comparison protocol the experts use (`CONTEXT_BASELINE_PROTOCOL.json`); run the verification below and write immutable evidence, with a family report per method printing both tables.

## Acceptance

- [ ] A01: Every read listed above is registered and implemented from its wiki predicate, with every operand classified through the ledger; no read is silently approximated.
- [ ] A02: Every call uses only data available at the snapshot clock; a future-perturbation control changes no historical call.
- [ ] A03: Full-history call frequencies per read are in bound or carry a diagnosis quoting the source page; bounds were written before the run and were not moved to fit it.
- [ ] A04: Baseline calls are issued on exactly the P2-01 rows and targets the experts use (identical row identities and availability masks).
- [ ] A05: Base rates and losses per read, per fold, carry the contract's bootstrap intervals and support counts; low-support cells are marked, not dropped.
- [ ] A06: `CONTEXT_BASELINE_PROTOCOL.json` defines the paired comparison every fitted expert must report (expert versus source read versus constant, session-frequency and price-only), and the promotion rule: upgrade only under the promotion gates, otherwise the source read is retained.
- [ ] A07: A read whose input is not owned returns `unsupported_owned_input` naming the operand and the source page; it appears in the registry with that status.
- [ ] A08: Evidence includes command exit codes, artifact hashes, coverage/unknown counts, runtime, actual output inspection and the task’s declared limitations. All predecessor receipts verify.
- [ ] A09: EVIDENCE_MATRIX.json resolves every acceptance key and assigned failure case to actual code, executed commands, hashed evidence and inspected output under ASSURANCE.md; artifact/identity/command forgeries fail.
- [ ] A10: The assigned silent-failure probes pass with sensitive positive and negative controls, honest native/unknown/job counts, and no stale evidence. Return review-ready artifacts; subphase admission additionally requires the coordinator’s matching passing GATE_REVIEW.json.

Assigned research cases: S07, S08, S11, S15, S18, S19, S28, S32 (see SILENT_FAILURES.md). The verifier cases S01 to S03 are cited from the P15-01 bound evidence, not re-probed here.
